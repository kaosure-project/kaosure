# แผนปิดงานระบบยืนยัน Kao ID — ตรวจจากไฟล์และฐานข้อมูล 26 กันยายน 2026

## ความหมายของงานรอบนี้
ทำเส้นทางผู้ใช้ส่งและติดตามเอกสารทีละหน้า ก่อนสร้างหน้าบริหาร Owner/Admin เต็มระบบ ไม่ให้การรอแต่งตั้งแอดมินหยุดงานฟอร์มผู้ใช้ แต่ห้ามเรียกทั้งระบบว่าเสร็จจนทดสอบการอนุมัติจริงและการออก Kao ID ผ่านแล้ว

ระบบแยกสามเรื่อง: การเป็นเจ้าของอีเมล/เบอร์, การพิสูจน์ตัวบุคคล, การเป็นเจ้าของบัญชีธนาคาร ผลผ่านเรื่องหนึ่งไม่ใช่ผลผ่านทุกเรื่อง

## สถานะที่ตรวจพบ
| ส่วน | หลักฐาน | ข้อสรุป |
|---|---|---|
| บัตรประชาชน | ภาพผู้ใช้แสดงกำลังตรวจสอบและปุ่มดูรูปสองด้าน | ส่งคำขอได้แล้ว ยังไม่ยืนยันผลอนุมัติและออก Kao ID จริง |
| หนังสือเดินทางเดิม | ใช้ DocumentUploadService ที่ชี้ kyc-documents แต่ฐานข้อมูลมี identity-documents; บันทึกเอกสารแยกจากคำขอ | ยังไม่ครบ จึงทำ R8A |
| ใบพำนัก | ResidencePermitPage: onPressed: null | ยังไม่มีการส่งเอกสารจริง |
| ธนาคาร | _onAddBank/_onManageBank แสดงข้อความยังไม่พร้อม | ยังไม่มีการเพิ่ม/จัดการจริงจากหน้า UI |
| อีเมล | ผู้ใช้รายงานยืนยันแล้ว, R7B ปรับสถานะร่วม, ภาพล่าสุดหน้ารวมยืนยันแล้ว | คงขั้นตอนเดิม; เปลี่ยนเมล E2E ยังต้องผู้ใช้เปิดลิงก์ |
| เบอร์โทร | มีขั้นตอนเดิมแต่ยังไม่ทดสอบ SMS จริง | ค้างผู้ให้บริการ/OTP |
| เจ้าหน้าที่ | R7C รองรับตรวจบัตรไทยตามสิทธิ์ kyc_officer | ยังไม่ใช่ระบบ Owner/Admin เต็ม และยังไม่รองรับตรวจ passport ใน queue นี้ |

## ลำดับส่งมอบ
### R8A — หนังสือเดินทาง: ส่งและติดตามคำขอ
ส่งมอบในชุดนี้:
- กรอก Given name(s) รวมชื่อกลาง / Family name, รองรับชื่อเดียวและลำดับแสดงนามสกุลก่อนชื่อ
- เก็บส่วนชื่อแยกจริง พร้อม full_name เพื่อรองรับโค้ดเดิม ไม่แยกชื่อเก่าด้วยการเดาจากช่องว่าง
- เลขหนังสือเดินทางเป็นข้อความ ไม่บังคับรูปแบบเลขบัตรไทย; ชื่อประเทศ/หน่วยงานผู้ออกตามเอกสาร
- วันเกิด วันออก วันหมดอายุ และภาพหน้าข้อมูลส่วนบุคคล
- ใช้ตัวตรวจ JPEG/PNG เดิมและพื้นที่ส่วนตัว identity-documents
- บันทึก document + file metadata + request ในธุรกรรมเดียว; สถานะ pending_review
- ส่งซ้ำด้วย request document ID เดิมเมื่อคำตอบหาย เก็บไฟล์เดิม ไม่ลบหลักฐานที่อาจบันทึกสำเร็จ
- เปิดกลับมาดูสถานะ วันหมดอายุ เหตุผลปฏิเสธ และรูป
- หนึ่งบัญชีมีคำขอ pending/under_review ครั้งละหนึ่งรายการตามระบบเดิม; แสดงเหตุผลถ้ามีคำขอบัตรไทยอยู่
- ภาษาไทย/อังกฤษ
ยังไม่รวม: ตรวจอนุมัติ passport, การออก Kao ID ด้วย passport, OCR/MRZ/liveness, การแจ้งหมดอายุ, การรับรองเอกสารของทุกประเทศ
ประเทศผู้ออกเป็นข้อความตามเอกสารในรุ่นนี้ ไม่ใช้ค่ากรอกเพื่อให้สิทธิ์อัตโนมัติ การกำหนดประเทศที่ให้บริการและการตรวจเอกสารเป็นงานแยกก่อนเปิดจริง

เกณฑ์ผ่าน: analyze/tests ผ่าน, บัญชีทดสอบที่ไม่มีคำขอค้างส่งรูปจริงสำเร็จ, เปิดหน้าใหม่พบคำขอเดิมและดูรูปได้ ทั้งไทยและอังกฤษ

### R8B — ใบพำนัก: หลักฐานประกอบตามกรณี
- กำหนดประเทศที่พำนักและประเภทเอกสาร เพื่อไม่สับสนว่าทุกประเทศใช้บัตรแบบเดียวกัน
- ชื่อตามเอกสาร เลขเอกสาร หน่วยงานผู้ออก วันออก/หมดอายุหรือประเภทไม่ระบุวันหมดอายุเมื่อรองรับจริง
- จำนวนรูปตามประเภทเอกสาร ไม่บังคับสองด้านสำหรับเอกสารที่มีหน้าเดียว
- ลิงก์กับบุคคลเดิม; ไม่สร้าง Kao ID ใหม่ และไม่ถือว่าใบพำนักทดแทนเอกสารตัวบุคคลทุกกรณี
- อัปโหลดส่วนตัว บันทึกพร้อมคำขอ เปิดกลับมา แก้ไขหลังถูกปฏิเสธ และตรวจหมดอายุ
- ปรับระบบคำขอให้แยกงานหลักกับหลักฐานประกอบอย่างชัดเจนก่อนอนุญาตส่งพร้อมกัน
เกณฑ์ผ่าน: ส่งจริง เปิดกลับมาได้ และไม่ยกระดับสิทธิ์จากการอัปโหลดเพียงอย่างเดียว

### R8C — บัญชีธนาคาร: สำหรับรับเงิน
- เริ่มบัญชีธนาคารไทย/THB ตามขอบเขต KaoSure ปัจจุบัน
- ธนาคาร ชื่อเจ้าของบัญชี เลขบัญชี (เก็บเป็นข้อความรักษาเลขศูนย์นำหน้า) หลักฐานและสถานะ
- เลขบัญชีแสดงแบบปิดบางส่วน; เข้าถึงเลขเต็มตามสิทธิ์และเหตุผลใช้งาน
- ชื่อตรงกับข้อมูล KYC ที่อนุมัติแล้ว; ชื่อต่างตัวอักษรหรือเปลี่ยนชื่อต้องมีขั้นตรวจเพิ่มเติม ไม่ตัดสินจากการลบเว้นวรรคอย่างเดียว
- เพิ่ม/ยกเลิก/ตั้งบัญชีรับเงินหลัก พร้อมตรวจว่าบัญชีที่ใช้รับเงินผ่านแล้ว
- การเปลี่ยนบัญชีรับเงินต้องยืนยันตัวตนซ้ำ แจ้งเจ้าของบัญชี และเก็บประวัติ
- แยกสถานะส่งหลักฐาน/ตรวจโดยเจ้าหน้าที่/ตรวจผ่านผู้ให้บริการจริง ไม่แสดงว่าเชื่อมธนาคารแล้วถ้าไม่มี provider
เกณฑ์ผ่าน: บันทึกและอ่านจริง ผู้ใช้อื่นอ่านไม่ได้ ผู้ใช้ตั้ง is_verified เองไม่ได้ และบัญชีไม่ผ่านตรวจถูกกันจากการรับเงิน

### R8D — เอกสารหมดอายุและการต่ออายุ
- ตรวจจากวันที่ฝั่งเซิร์ฟเวอร์ และกำหนดเขตเวลาของระบบให้สอดคล้องกัน
- แจ้งเตือนในแอปล่วงหน้า (เสนอ 30 และ 7 วัน) พร้อมปุ่มอัปเดตเอกสาร
- งานตามเวลาทำซ้ำได้โดยไม่ส่งแจ้งเตือนซ้ำ; แยกช่องทางอีเมลที่เชื่อมจริงจาก notification ในแอป
- เก็บเอกสารเดิมและประวัติ สร้างรุ่นใหม่; ระหว่างรอตรวจใช้สิทธิ์ตามนโยบายที่กำหนด
- เมื่อหมดอายุจำกัดเฉพาะบริการที่ต้องใช้หลักฐานปัจจุบัน ไม่ลบบัญชีหรือเปลี่ยนเลข Kao ID
- แก้ข้อจำกัด R7A ที่ approved document เดิมขวางการส่งใหม่ แม้วันหมดอายุผ่านแล้ว ก่อนเปิดต่ออายุบัตรไทย

### R9 — Owner / Admin / ตรวจอนุมัติ
- Owner อ๊อฟคนเดียว ผูกกับบัญชีที่ระบุตัวตนและตรวจสิทธิ์แล้ว
- มอบหมายหน้าที่โดย Kao ID/บัญชีเป้าหมาย บทบาท ขอบเขต วันเริ่ม/หมดอายุ ผู้มอบหมายและเหตุผล
- เจ้าหน้าที่เห็นเฉพาะงานตามสิทธิ์ ห้ามตรวจของตนเอง และตรวจสิทธิ์ซ้ำฝั่งเซิร์ฟเวอร์ทุกครั้ง
- ขยายคิว/หน้าตรวจให้แยกบัตรไทย หนังสือเดินทาง ใบพำนัก ธนาคาร
- อนุมัติ/ปฏิเสธ/ขอเอกสารเพิ่ม บันทึกผู้ทำและเวลา; ป้องกันเจ้าหน้าที่สองคนบันทึกผลขัดกัน
- ยังไม่ได้ยืนยันว่าต้องตรวจสองชั้นเสมอ ห้ามสมมติแทนผู้ใช้; ออกแบบเพิ่มผู้ตรวจ/ผู้อนุมัติแยกได้ภายหลัง
- ขยายเกณฑ์ออก Kao ID ให้ใช้ passport ที่อนุมัติได้; ป้องกันเลขซ้ำและการลงทะเบียนบุคคลเดิมด้วยเอกสารหลายชนิด

### R10 — ตรวจพร้อมใช้งานจริง
- ทดสอบสมาชิกทั่วไป/เจ้าของเอกสาร/เจ้าหน้าที่/Owner ครบสิทธิ์, session เปลี่ยน, เน็ตหลุด, กดซ้ำ, เอกสารเก่า, หมดอายุ
- สถานะหน้าเอกสารและหน้ารวมต้องตรงกัน; error ต้องมีทางแก้และไม่เผยข้อมูลฐานข้อมูล
- จัดการไฟล์อัปโหลดค้างที่ไม่มีคำขอโดยไม่ลบหลักฐานที่ใช้งานอยู่
- กำหนดการเก็บรักษา/ลบข้อมูลเอกสาร สิทธิ์ผู้ใช้ ประวัติการเข้าถึง และช่องทางขอความช่วยเหลือ
- ประเมินว่าต้องตรวจความเป็นเจ้าของเอกสารด้วยขั้นตอนเพิ่มเติมหรือผู้ให้บริการใด การเก็บรูปเพียงอย่างเดียวไม่พิสูจน์ว่าผู้ส่งเป็นเจ้าของเอกสาร
- ปิดรายการ security advisor เดิมที่เกี่ยวข้องก่อนเปิดจริง และทดสอบกู้คืนข้อมูล
- Wallet แยกงานภายหลัง: การยืนยันธนาคารไม่เท่ากับมีระบบกระเป๋าเงิน/รับชำระแล้ว

## กฎปิดงานทุกหน้า
1. อ่านโค้ดเดิมและฐานข้อมูลก่อนแก้
2. แปลข้อความทั้งสำเร็จ/ผิดพลาด/สถานะว่าง
3. ทดสอบธุรกรรมและสิทธิ์ฝั่งฐานข้อมูล
4. Flutter analyze และ tests ผ่านบนเครื่องพัฒนา
5. ทดลองใช้งานจริงจาก Chrome เปิดกลับมาและตรวจสถานะ
6. ระบุว่างานผ่านเฉพาะส่งเอกสาร หรือผ่านอนุมัติครบวงจร ห้ามรวมสองสถานะนี้เข้าด้วยกัน
