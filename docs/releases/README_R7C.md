# Kao ID R7C — ตรวจเอกสารจริงและออก Kao ID

ใช้ต่อจาก R7B ที่ analyzer สะอาดและผ่าน 124 tests แล้ว

## สิ่งที่เชื่อมแล้ว
- หน้าคิวตรวจบัตรประชาชนเรียกข้อมูลจาก Supabase จริง แสดงรายการรอตรวจสอบเก่าสุด 50 รายการ
- เมนูเจ้าหน้าที่ปรากฏในหน้ายืนยันตัวตนเฉพาะบัญชีที่มี assignment บทบาท kyc_officer ที่ยังใช้งานอยู่
- เปิดภาพส่วนตัวด้วยสิทธิ์เจ้าหน้าที่ที่ตรวจบนเซิร์ฟเวอร์ ไม่สร้าง public URL
- ต้องเปิดภาพทั้งสองด้านและยืนยันว่าได้ตรวจแล้วก่อนกดอนุมัติใน UI
- อนุมัติ/ปฏิเสธบันทึกสถานะเอกสาร คำขอ สถานะรวม และ audit log ในธุรกรรมเดียวกัน
- ผู้ตรวจอนุมัติเอกสารของตัวเองไม่ได้ การปฏิเสธต้องมีเหตุผล
- ป้องกันบัตรประชาชนเลขเดียวกันที่อนุมัติแล้วไปผูกอีกบัญชี
- หน้าผู้ใช้แสดง Kao ID จริงจากฐานข้อมูล; เมื่อผ่านการตรวจสามารถกดขอออก Kao ID
- เซิร์ฟเวอร์ตรวจสถานะบัญชีและหลักฐานอนุมัติก่อนออก ID ใหม่ และออกซ้ำให้ได้เลขเดิม
- ปิดสิทธิ์ client ในการแก้ role/account_status/ค่าความน่าเชื่อถือของโปรไฟล์โดยตรง คงสิทธิ์แก้ชื่อ รูป ประวัติ ภาษาและข้อมูลโปรไฟล์ทั่วไปที่โค้ดเดิมใช้
- ข้อความใหม่ครบไทย–อังกฤษ

## ฐานข้อมูล
Migration `kyc_review_and_issuance_r7c` ติดตั้งแล้ว ไม่ต้องรัน docs/R7C_backend.sql ซ้ำ
ไม่มีการแต่งตั้งเจ้าหน้าที่จริง ไม่มีการอนุมัติเอกสารจริง และไม่มีการออก Kao ID ให้บัญชีจริงโดยผู้ช่วย

SQL regression ผ่านทั้งส่งเอกสาร/อนุมัติ/ออก ID ซ้ำ และปฏิเสธ/กันออก ID ใหม่ ใช้ข้อมูลทดสอบและสิทธิ์ชั่วคราวภายใน transaction ที่ ROLLBACK ทั้งหมด
ตรวจหลังทำงาน: ไม่มีข้อมูลทดสอบค้าง, anon เรียกอนุมัติไม่ได้, client แก้ role ไม่ได้ แต่แก้ display_name ได้
ผลนี้ไม่ใช่หลักฐานการส่งรูปจริงผ่านเบราว์เซอร์หรือการตรวจเอกสารโดยเจ้าหน้าที่

## สิ่งที่ต้องระบุก่อนใช้งานเจ้าหน้าที่
จากการตรวจล่าสุด ยังไม่มี admin assignment บทบาท KYC Officer จริง
อ๊อฟต้องระบุอีเมลหรือ User ID ของบัญชีที่จะเป็นเจ้าหน้าที่ บัญชีต้องสมัครอยู่แล้ว และแยกจากบัญชีผู้ส่งเอกสาร
ผู้ช่วยจะตรวจบัญชีและขอบเขตสิทธิ์ก่อนแต่งตั้ง ไม่เลือกหรือสร้างผู้มีอำนาจแทนอ๊อฟโดยอัตโนมัติ
เมนูไม่ปรากฏสำหรับบัญชีปกติเป็นพฤติกรรมที่ตั้งใจไว้
การตั้ง Owner คนแรกและระบบบริหารสิทธิ์เต็มรูปแบบเป็นงาน Governance แยกจากการแต่งตั้ง KYC Officer นี้

## ขั้นตอนพิสูจน์การทำงานจริง
1. ผู้สมัครเข้าสู่ระบบ ส่งบัตรประชาชนผ่าน R7A แล้วเปิดกลับมา ตรวจว่ารูปทั้งสองด้านเปิดได้
2. เจ้าหน้าที่ที่ได้รับสิทธิ์เข้าสู่ระบบอีกบัญชี → ยืนยันตัวตน → ตรวจเอกสารยืนยันตัวตน
3. เปิดคำขอ ตรวจรูปและข้อมูลจริง จึงอนุมัติหรือปฏิเสธพร้อมเหตุผลตามผลตรวจ ห้ามอนุมัติเพียงเพื่อให้ระบบแสดงว่าผ่าน
4. ผู้สมัครกดตรวจสอบอีกครั้ง สถานะต้องเปลี่ยนตามผลเจ้าหน้าที่ และมีประวัติ
5. หากอนุมัติแล้ว ผู้สมัครกดขอออก Kao ID ต้องได้เลขจากฐานข้อมูล เปิดใหม่เลขต้องเหมือนเดิม
6. หากปฏิเสธ ต้องเห็นเหตุผลและส่งเอกสารใหม่ได้ โดยยังออก ID ใหม่ไม่ได้
7. ลองบัญชีปกติต้องไม่มีสิทธิ์เปิดคิวหรืออ่านรูปของผู้อื่น

## อีเมล
ขั้นตอนขอเปลี่ยนอีเมล R6C และการแสดงสถานะ R7B ใช้ Auth จริงอยู่แล้ว ชุดนี้คงไว้
การทดสอบส่งจริงต้องให้อ๊อฟกรอกอีเมลใหม่ที่ตนเข้าถึงได้ในแอป เปิดลิงก์ที่ระบบส่ง แล้วกลับมากดตรวจสอบอีกครั้ง
ต้องเห็นอีเมลใหม่และเข้าสู่ระบบด้วยอีเมลใหม่ได้ จึงปิดผล E2E ได้ ไม่ต้องส่งรหัสผ่านหรือลิงก์ยืนยันให้ผู้ช่วย
ยังไม่ได้ยืนยันการตั้งค่า SMTP/Secure Email Change หรือส่งเมลจริงในรอบนี้

## ขอบเขต
- หน้าตรวจในชุดนี้รองรับบัตรประชาชนจาก R7A เท่านั้น ยังไม่ตรวจหนังสือเดินทาง/ใบพำนัก/ธนาคาร
- ตรวจซ้ำจากเลขบัตรที่บันทึก ไม่ใช่การเชื่อมทะเบียนราษฎร์หรือพิสูจน์ความแท้เอกสารอัตโนมัติ
- Email Auth auto-confirm ยังไม่ใช่หลักฐานยืนยันการครอบครองสำหรับสิทธิ์ซื้อขาย ระบบสิทธิ์ธุรกรรมยังต้องแยกตรวจ
- Phone OTP, การสแกนไฟล์ฝั่ง server, การเก็บกวาดไฟล์กำพร้า, ระยะเก็บเอกสาร และ security advisor เดิมยังอยู่ในงานก่อน production
- การทดสอบ UI ใช้ข้อมูลจำลอง แต่โค้ดแอปใน lib ไม่มีการอนุมัติหรือออก Kao ID จำลอง
- ชุดนี้พร้อมให้ตรวจและทดสอบบนระบบที่เชื่อมจริง ไม่ใช่การรับรองว่า Kao ID ทุกหมวดพร้อม production
