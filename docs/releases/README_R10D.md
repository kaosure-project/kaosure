# Kao ID R10D — ปิดการใช้งานบัญชีและจำกัดเซสชัน

ต่อจาก R10C โดยรวมไฟล์ UI ที่ R10D ต้องใช้จาก R10C ไว้แล้ว คง UUID, รหัส ACC, Kao ID และขั้นยืนยันอีเมลเดิม

## ทำได้ในชุดนี้
- Owner เปิด ศูนย์ผู้ดูแล Kao ID → คำขอเกี่ยวกับบัญชี → รายละเอียดคำขอปิดบัญชี
- ตรวจข้อมูลจริงอีกครั้งตอนยืนยัน ต้องมีเหตุผลและกดยืนยัน ไม่ให้ปิดตัวเองหรือ Owner
- ถ้าบัญชีผ่านเงื่อนไข ปิดการใช้งาน ยุติ Auth sessions/refresh tokens เดิม ถอนสิทธิ์เจ้าหน้าที่และสิทธิ์เดิมที่ครอบคลุม ยกเลิกคำขอ KYC ที่รอตรวจ
- เก็บ Kao ID หมายเลขเดิมโดยเปลี่ยนเป็น closed พร้อมเก็บเอกสาร ประวัติ รหัสบัญชี และบันทึกผู้ดำเนินการ/บทบาท
- ส่งคำสั่งปิดเดิมซ้ำไม่ทำประวัติซ้ำ
- บล็อกโทเคนเก่าผ่าน API และเพิ่มข้อจำกัด RLS สำหรับตาราง/Storage
- หน้าแอปตรวจเมื่อเปิด กลับเข้าเว็บ และทุก 15 วินาที เมื่อปิดบัญชีจะซ่อนหน้าปกติ
- เข้าสู่ระบบใหม่ได้แบบจำกัดเพื่อดู/ส่ง/ยกเลิกคำขอกลับมาใช้ ไม่มีการคืนสิทธิ์หรือ Kao ID เป็น active อัตโนมัติ
- ยังใช้ลิงก์รีเซ็ตรหัสผ่านได้ในหน้าที่จำกัด
- ภาษาไทย อังกฤษ ญี่ปุ่น จีน พม่า ลาว เวียดนาม (คงไฟล์จีน fallback)

## ขอบเขตการตรวจภาระ
ตอนนี้อนุญาตปิดเฉพาะบัญชีที่ไม่มีประวัติบริการซึ่งยังต้องตีความเงื่อนไข และกระเป๋าเงินไม่มียอดคงเหลือ/ยอดพักเงิน
ตรวจ orders, order_items, disputes, withdraw/refund/return/cancel requests, shops, organization memberships/delegations, business registrations, approval requests, API keys, OAuth clients, commission, tax records, invoice, receipt และธุรกรรมผ่าน wallet

หากมีประวัติบริการ แม้เป็นรายการเก่าที่เสร็จแล้ว ระบบยังบล็อกและแสดงชื่อตาราง/จำนวนจริง ไม่ถือว่ามีหนี้เสมอไป และ **ห้ามลบประวัติเพื่อให้ผ่าน** ต้องต่อเงื่อนไขปิดของบริการนั้นอย่างชัดเจนในชุดถัดไป สินค้าผูกกับ shops จึงถูกครอบคลุมด้วยการบล็อกบัญชีที่มีร้านค้า

มี trigger ป้องกันการสร้าง/แก้รายการบริการที่ครอบคลุมให้บัญชีปิด ทั้งจากสมาชิกและผู้เขียนข้อมูลที่มีสิทธิ์สูง การเพิ่มบริการ/Edge Function ใหม่ต้องใช้การตรวจสถานะเดียวกัน งานระบบที่ใช้ service_role ไม่ควรข้ามการตรวจนี้

## ติดตั้งบนเครื่อง
ฐานข้อมูลติดตั้งแล้ว ไม่ต้องรัน database/closure.sql ซ้ำ ไฟล์ SQL แนบไว้สำหรับตรวจทานและเก็บเวอร์ชัน

```powershell
$backupName = 'kaoid_before_R10D_' + (Get-Date -Format 'yyyyMMdd_HHmmss') + '.zip'
Compress-Archive -Path lib,test -DestinationPath $backupName
Expand-Archive -LiteralPath .\kaoid_account_closure_R10D.zip -DestinationPath . -Force
flutter gen-l10n
flutter analyze
flutter test test/localization/closure_r10d_test.dart
flutter test test/localization
```

หยุดแอปเดิมแล้วเปิดใหม่ด้วยคำสั่งรันเดิมของโปรเจกต์ เพื่อโหลดตัวตรวจสถานะบัญชีที่เพิ่มใน App

## ผลตรวจที่ทำแล้ว
- SQL ทดสอบด้วยข้อมูลชั่วคราว และ ROLLBACK ทั้งหมด: ปฏิเสธการปิดด้วยสมาชิก, บล็อกเงินค้าง, ปิดบัญชีที่ผ่านเงื่อนไข, ส่งซ้ำ, เก็บ Kao ID เดิม, audit บทบาท Owner, ลบ session, ป้องกันบริการใหม่หลังปิด, ปฏิเสธ session เก่า, จำกัด session ใหม่, รับคำขอกลับมาใช้โดยไม่คืนบัญชี
- ยืนยันว่าไม่มีบัญชีจริงถูกปิดระหว่างการพัฒนา
- ตรวจ ARB key ครบ/รักษาข้อความเดิม และตรวจโครงสร้างวงเล็บ Dart เบื้องต้น
- ยังไม่ได้รัน Flutter analyze/widget tests ที่นี่ เพราะไม่มี Flutter SDK ผล SQL ไม่ทดแทนผล Flutter หรือการทดลอง Auth/Storage ผ่านเว็บจริง
- Security advisors: ตาราง private ใหม่ตั้งใจไม่มี client policy; ยังมีคำเตือนเดิมของฟังก์ชัน public/extension/Auth ที่ไม่ใช่งาน R10D ต้องตรวจต่อก่อนเปิดบริการเต็มรูปแบบ

## ทดลองจริงด้วยบัญชีทดสอบเท่านั้น
1. บัญชีทดสอบที่ไม่มีภาระหรือประวัติบริการ ส่งคำขอปิดบัญชี (อย่าใช้ Owner หรือบัญชีหลัก)
2. เปิดบัญชีทดสอบในสองหน้าต่าง/อุปกรณ์ จากนั้น Owner อ่านคำขอ ใส่เหตุผลและกดปิดจริง
3. ตรวจว่าบัญชีถูกปิด ประวัติแสดงผู้ดำเนินการและเหตุผล และ Kao ID/ACC เดิมยังอยู่
4. หน้าต่างสมาชิกเดิมต้องไม่ทำรายการสำเร็จ และแสดงว่าเซสชันสิ้นสุดเมื่อกลับเข้าเว็บหรือถึงรอบตรวจ
5. ออกจากระบบและเข้าใหม่ ต้องเห็นเฉพาะหน้าบัญชีปิดและขอกลับมาใช้ เปิด URL หน้าปกติโดยตรงไม่ได้
6. ส่งคำขอกลับมาใช้ แล้วดูใน Owner ได้ แต่ยังไม่อนุมัติเพื่อคืนสิทธิ์อัตโนมัติ
7. ลิงก์รีเซ็ตรหัสผ่านและการเข้าสู่ระบบของบัญชีที่ active ต้องยังทำงานปกติ

การปิดไม่เรียกเก็บไฟล์ที่ดาวน์โหลดไปแล้วกลับคืน และไม่ได้ลบข้อมูลส่วนบุคคลทั้งหมด

## ยังไม่ถือว่าเสร็จ
- ตรวจตัวตนใหม่สำหรับคำขอกลับมาใช้ และคืน Kao ID เดิมให้ active (รวมการสมัครใหม่แล้วเชื่อมตัวตนเดิม)
- เงื่อนไขปิดสำหรับบัญชีที่มีประวัติบริการ/การเงิน
- การกำหนดระยะเก็บข้อมูลและลบข้อมูลตามประเภท
- เพิกถอน KYC, เอกสารหมดอายุ/ส่งทดแทน, SMS OTP จริง, อีเมลแจ้งเหตุการณ์จริง, ทดสอบโหลด
- ปิดบัญชีนี้ไม่ใช่การลบ Auth user และไม่อนุมัติ/ปฏิเสธ KYC ใหม่แทนเจ้าหน้าที่
