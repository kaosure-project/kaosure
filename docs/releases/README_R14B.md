# R14B — แจ้งเตือนเจ้าหน้าที่และเปิดรายการจากข้อมูลจริง
ติดตั้งต่อจาก R14A ที่อ๊อฟทดสอบแล้ว (analyze สะอาด, targeted 20, รวม 358 ผ่าน)

## ทำแล้ว
- ใช้กล่องเดิมและจำนวนยังไม่อ่าน ไม่สร้างระบบข้อความซ้ำ
- คำขอบัตร/หนังสือเดินทาง/ใบพำนัก/คืนบัญชี และธนาคารใหม่ แจ้ง Owner และ KYC Officer ที่มีบทบาทใช้งานอยู่ โดยไม่แจ้งผู้สมัครให้ตรวจตัวเอง
- เมื่อคนแรกเสนอผลตามนโยบายสองคน แจ้งผู้ตรวจคนอื่น ยกเว้นผู้สมัครและคนแรก
- เมื่อผู้ตรวจเห็นต่าง แจ้งให้เริ่มตรวจใหม่ คำขอไม่ถูกอนุมัติหรือปฏิเสธอัตโนมัติ
- มอบหมาย/ถอนบทบาทผ่านระบบเดิม แจ้งผู้ได้รับผล
- คงการแจ้งผลตรวจให้สมาชิกของเดิม
- แตะข้อความ = ทำเครื่องหมายอ่านแล้ว; ปุ่มเปิดรายการด้านขวา = อ่านแล้วและเปิดรายละเอียดปัจจุบัน
- เปิดคำขอรอตรวจตรงรายการ ไม่ติดข้อจำกัด 50 รายการของหน้าคิวเดิม
- เปิดผลสมาชิกแสดงสถานะและเหตุผลจากตารางจริง ส่วนบทบาทอ่านสถานะปัจจุบัน ไม่ใช้ข้อความแจ้งเตือนเก่าเป็นสิทธิ์
- ตรวจผู้รับและสิทธิ์ใหม่บนเซิร์ฟเวอร์ทุกครั้ง กันอ่านข้ามบัญชี/ถอนสิทธิ์แล้วเปิดหลักฐาน
- รายการที่จบแล้วหรือไม่พร้อมตรวจจะแสดงข้อความ ไม่เปิดหลักฐานผ่านทางเก่า
- ข้อความครบเจ็ดภาษาและ zh fallback

## หลักฐาน
SQL rollback tests ผ่าน: แจ้งผู้รับที่ถูกต้อง, กัน self/คนแรก, ส่งซ้ำไม่ซ้ำ, เปิดคำขอตรงรายการ, กันข้ามบัญชี, ถอนสิทธิ์แล้วเปิดไม่ได้, คำขอจบแล้วเปิดหลักฐานไม่ได้, สมาชิกยังได้รับผล, คำขอธนาคาร, มอบหมาย/ถอนบทบาท และ client เรียก helper โดยตรงไม่ได้
ตรวจไวยากรณ์ Dart และ key ภาษาแล้ว เพิ่ม Flutter tests 25 รายการ แต่ยังไม่ได้รัน Flutter ที่นี่
ผล SQL ใช้ข้อมูลชั่วคราวและย้อนกลับ ไม่ได้ส่งคำขอหรือมอบหมายสิทธิ์จริงให้สมาชิก

## ทดลองจริง
1. สมาชิกทดสอบส่งคำขอใหม่ เจ้าหน้าที่ที่มีสิทธิ์ต้องเห็นจำนวนยังไม่อ่านเพิ่ม (รีเฟรชหรือรอรอบเดิมประมาณ 60 วินาทีขณะหน้าเปิด)
2. กดเปิดรายการ ต้องเป็นคำขอเดียวกัน และจำนวนที่ยังไม่อ่านลดลง
3. เมื่อเปิดนโยบายสองคนแล้ว คนแรกเสนอผล คนที่สองได้รับแจ้ง เปิดและตรวจได้ สมาชิกยังไม่ถูกอนุมัติก่อนครบสองคน
4. เมื่อตรวจเสร็จ สมาชิกได้รับผล กดเปิดดูสถานะจริงและเหตุผลกรณีไม่ผ่าน
5. Owner ถอนสิทธิ์บัญชีทดสอบ ผู้ได้รับผลเห็นแจ้งเตือน และเปิดคำขอจากแจ้งเตือนเก่าต้องถูกปฏิเสธ
6. เปลี่ยนบัญชี/เปิดเว็บใหม่ จำนวนและรายการต้องเป็นของบัญชีปัจจุบันเท่านั้น

## ขอบเขต
- เฉพาะเหตุการณ์ใหม่หลังติดตั้ง ไม่สร้างแจ้งเตือนย้อนหลัง คำขอเก่ายังเข้าทางคิวเดิม
- เจ้าหน้าที่ที่ได้รับสิทธิ์ภายหลังยังดูคิวเดิมได้ แต่ไม่ส่งทุกคำขอเก่าให้ย้อนหลัง
- ประเภทงานยังใช้สิทธิ์ KYC Officer กลางเดิม ไม่มีการตั้งบทบาทตรวจแต่ละเอกสารใหม่
- การรับแจ้งเตือนไม่ให้สิทธิ์อ่านหลักฐาน ต้องมีสิทธิ์ปัจจุบันและ MFA ตามนโยบาย
- ไม่เปิด MFA หรือนโยบายสองคนเอง และไม่ตั้งเจ้าหน้าที่จริงแทน Owner
- เก็บงานอีเมลลงคิวเดิม แต่ยังไม่ยืนยันส่งอีเมลแจ้งเหตุการณ์จริง (ต่างจากอีเมลยืนยันบัญชีที่เคยผ่าน)
- ประกาศถึงสมาชิกทุกคน และการแจ้งเตือนเมื่อความเห็นหมดอายุอัตโนมัติยังไม่อยู่ในชุดนี้
- รูปแบบ fan-out นี้เหมาะกับทีมตรวจขนาดเล็ก ไม่ใช่หลักฐานทดสอบรองรับเจ้าหน้าที่จำนวนมาก
