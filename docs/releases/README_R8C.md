# R8C — ส่งบัญชีธนาคารเพื่อตรวจสอบ

ต่อจาก R8B ที่ผ่าน 154 tests แล้ว ไม่ใช่โปรเจกต์ใหม่ ใช้ทับไฟล์ในโปรเจกต์เดิม

## สิ่งที่เพิ่ม
- หน้าบัญชีธนาคาร: เพิ่มชื่อธนาคาร ชื่อเจ้าของบัญชีตามเอกสาร เลขบัญชี (เก็บศูนย์นำหน้า) สาขาไม่บังคับ และประเภทออมทรัพย์/กระแสรายวัน
- รอบนี้รองรับบัญชีบุคคลในประเทศไทย สกุล THB บัญชีองค์กรและต่างประเทศยังไม่เปิด
- เลือกภาพหลักฐาน JPEG/PNG ผ่านตัวตรวจไฟล์เดิม: จำกัดขนาด/มิติ ตรวจภาพ หมุนตาม EXIF และแปลง JPEG ลบ metadata ก่อนอัปโหลด
- อัปโหลดพื้นที่ส่วนตัว identity-documents แล้วบันทึก bank_accounts กับ financial_verifications ในธุรกรรมเดียว สถานะ pending ทั้งคู่
- ผู้ใช้ตั้ง is_verified, name_match_status, บัญชีหลัก หรือผู้อนุมัติเองไม่ได้
- หมายเลขแสดง 4 หลักท้ายผ่าน RPC รายการบัญชีไม่ส่งเลขเต็มกลับมา
- รายการธนาคารรอตรวจได้ครั้งละหนึ่งรายการ แยกจากคำขอบัตร/หนังสือเดินทาง/ใบพำนัก
- ส่งซ้ำเมื่อการตอบกลับหายใช้ UUID และข้อมูลเดิม ไม่สร้างรายการซ้ำ ปิดแก้ไขระหว่างรอส่งซ้ำ
- เปิดหน้ากลับมาดูสถานะและภาพที่ส่งได้ ผู้ใช้คนอื่นไม่มีสิทธิ์อ่าน
- เมื่อเปลี่ยนบัญชี/ออกจากระบบ ซ่อนข้อมูลและภาพที่เปิดอยู่
- แก้ BankVerificationModel ไม่ตีสถานะ rejected/expired เป็น pending
- หน้ารวมอ่านรายการล่าสุดด้วย RPC แทน maybeSingle ที่ล้มเมื่อมีหลายบัญชี
- ข้อความใหม่ครบไทย–อังกฤษ รวมข้อผิดพลาดและคำแนะนำ

## การติดตั้ง
ฐานข้อมูลติดตั้ง migration bank_submission_r8c ในโปรเจกต์เดิมแล้ว ไม่ต้องคัดลอก SQL ไปรันซ้ำ
ไฟล์ docs/R8C_backend.sql เป็นสำเนาสำหรับตรวจทานเท่านั้น

```powershell
$backupName = 'kaoid_before_R8C_' + (Get-Date -Format 'yyyyMMdd_HHmmss') + '.zip'
Compress-Archive -Path lib,test -DestinationPath $backupName
Expand-Archive -LiteralPath .\kaoid_bank_R8C.zip -DestinationPath . -Force
flutter gen-l10n
flutter analyze
flutter test test/localization/bank_r8c_test.dart
flutter test test/localization
```

Flutter ยังไม่ได้รันในสภาพแวดล้อมที่จัด ZIP นี้ เพิ่มเทสต์ธนาคาร 11 รายการและปรับ fixture ใน kyc_details_r6d_test.dart ให้ใช้ repository ใหม่
คาดว่ารวมเป็น 165 รายการเมื่อรวมกับ R8B 154 รายการ แต่ต้องอ้างผลจริงจากเครื่องผู้ใช้

## ผลตรวจที่ทำแล้ว
SQL regression ผ่านและ ROLLBACK ทั้งหมด: ไฟล์หายต้องไม่บันทึก, บันทึกพร้อมคำขอ, pending เท่านั้น, เก็บศูนย์นำหน้า, เลขปิดบางส่วน, ส่งซ้ำไม่ซ้ำ, ข้อมูล retry เปลี่ยนไม่ได้, กันคำขอซ้อน, กัน self-verification และอ่านข้ามบัญชี
ไม่ได้ส่งรูปไป Storage จริงในการทดสอบ SQL ใช้ metadata ชั่วคราว จำนวน bank_accounts และ financial_verifications หลัง rollback ยังคง 0
ตรวจ Thai/English keys และ getter ที่ใช้ในไฟล์ใหม่ตรงกัน

## ทดลองจริงบนเครื่อง
1. เข้า การยืนยันตัวตน → ข้อมูลเพิ่มเติม → บัญชีธนาคาร
2. กดเพิ่ม กรอกบัญชีของตนเองและแนบภาพที่เห็นชื่อธนาคาร ชื่อเจ้าของบัญชี และเลขบัญชี
3. กดส่ง ต้องแสดงรอตรวจและเลขท้าย 4 หลัก ไม่แสดงว่าผ่านแล้ว
4. ออกจากหน้าและกลับเข้าใหม่ ตรวจข้อมูลและเปิดภาพหลักฐาน
5. เปิดภาษาอีกภาษา ตรวจข้อความและสถานะ
6. ยังไม่เพิ่มรายการซ้ำเมื่อมีรายการรอตรวจ ไม่ต้องลบคำขอบัตรเดิม

## ขอบเขตที่ยังไม่เสร็จ
- การอนุมัติ/ปฏิเสธโดย Owner/เจ้าหน้าที่ และ audit ของการตรวจธนาคาร ต้องต่อกับระบบสิทธิ์ตามแผน R9
- ไม่ได้เชื่อมตรวจบัญชีกับธนาคารภายนอก ไม่โอนเงิน ไม่เปิด Wallet ไม่ตั้งบัญชีรับเงินอัตโนมัติ
- bank_code='manual' เป็นป้ายสำหรับการตรวจเอกสาร ไม่ใช่ clearing code; ชื่อธนาคารกรอกตามหลักฐาน ไม่ได้ตรวจว่ามีบัญชีจริงโดย API
- อัปโหลดสำเร็จแต่บันทึกไม่สำเร็จอาจมีไฟล์ส่วนตัวค้าง จง retry รายการเดิม การล้างไฟล์ค้างต้องออกแบบงาน retention แยก ไม่ลบเมื่อยังไม่ทราบผลบันทึก
- หลักฐานผ่านการตรวจชนิด/ขนาดภาพฝั่งแอปและ metadata ฝั่ง SQL ยังไม่มีระบบสแกนไฟล์ฝั่งเซิร์ฟเวอร์
- หน้าแสดงสถานะธนาคารใหม่ไม่แสดงชื่อผู้ตรวจ/หมายเหตุภายในต่อผู้ใช้
- การแก้ไข/ถอนบัญชีที่ยืนยันแล้ว และบัญชีหลัก ต้องเพิ่มพร้อมสิทธิ์และกติกาการจ่ายเงิน
