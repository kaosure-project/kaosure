# R9C — ตรวจเอกสารและบัญชีธนาคาร

ติดตั้งต่อจาก R9B ที่ analyze ผ่านและชุดทดสอบรวม 213 รายการผ่านแล้ว

## ส่วนที่เพิ่ม
- คิวเจ้าหน้าที่รวมบัตรประชาชน หนังสือเดินทาง ใบพำนัก และบัญชีธนาคาร
- จำนวนภาพที่ต้องเปิดตรวจก่อนอนุมัติตรงตามประเภท: บัตรประชาชน 2, หนังสือเดินทาง 1, ใบพำนักแบบกระดาษ 1/แบบบัตร 2, ธนาคาร 1
- อนุมัติ/ปฏิเสธพร้อมเหตุผล บันทึกผู้ตรวจและประวัติในฐานข้อมูลเดิม
- หนังสือเดินทางที่ผ่านตรวจและยังไม่หมดอายุใช้ขอ Kao ID ได้ ขอซ้ำคืน ID เดิม
- ใบพำนักเป็นหลักฐานประกอบ ไม่ให้สิทธิ์ออก Kao ID เพียงอย่างเดียว
- ธนาคารต้องมีหลักฐานและชื่อบัญชีตรงกับเอกสารหลักที่ผ่านตรวจ ชุดนี้เทียบชื่อหลังปรับตัวพิมพ์และช่องว่าง ไม่แปลงชื่อข้ามภาษา ชื่อต่างรูปแบบต้องตรวจแก้ข้อมูลก่อน ไม่สรุปว่าเป็นการทุจริต
- อนุมัติธนาคารไม่ตั้งบัญชีรับเงินเริ่มต้นและไม่เปิดระบบจ่ายเงินอัตโนมัติ
- ประวัติธนาคารใช้เหตุการณ์และเวลาตรวจจริง ไม่ใช้สถานะปัจจุบันสร้างวันอนุมัติย้อนหลัง
- ข้อความที่เพิ่ม/เปลี่ยนมีครบไทย อังกฤษ ญี่ปุ่น จีนตัวย่อ พม่า ลาว เวียดนาม

## ติดตั้ง
```powershell
$backupName = 'kaoid_before_R9C_' + (Get-Date -Format 'yyyyMMdd_HHmmss') + '.zip'
Compress-Archive -Path lib,test -DestinationPath $backupName
Expand-Archive -LiteralPath .\kaoid_review_R9C.zip -DestinationPath . -Force
flutter gen-l10n
flutter analyze
flutter test test/localization/review_r9c_test.dart
flutter test test/localization
```
ฐานข้อมูลติดตั้ง migration multi_document_and_bank_review_r9c แล้ว ไม่ต้องรัน SQL ซ้ำ
ไฟล์ database เป็นหลักฐานการเปลี่ยนแปลง ไม่ใช่คำสั่งให้รันกับโปรเจกต์อื่นโดยไม่ตรวจโครงสร้างก่อน

## ผลตรวจที่ทำแล้ว
- SQL: ใบพำนักไม่ให้ ID; หนังสือเดินทางผ่านตรวจขอ ID ได้; ขอซ้ำไม่ออก ID ใหม่
- SQL: เอกสารหมดอายุ/ขาดไฟล์ และชื่อธนาคารไม่ตรงถูกบล็อก
- SQL: อนุมัติซ้ำไม่เพิ่มประวัติซ้ำ; ธนาคารไม่ถูกตั้งเป็นบัญชีรับเงินเริ่มต้น; ถอนสิทธิ์แล้วเปิดหลักฐานไม่ได้
- ทดสอบ SQL ด้วยข้อมูลชั่วคราวและ rollback ทั้งหมด ไฟล์ Storage ในการทดสอบเป็น metadata ไม่ใช่ภาพอัปโหลดจริง
- ตรวจ key ภาษาและการอ้างอิงข้อความแล้ว เพิ่ม Flutter tests 11 รายการ แต่ยังไม่ได้รัน Flutter ที่นี่

## ทดสอบใช้งานจริงตามลำดับ
1. Owner เข้า จัดการสมาชิก → จัดการเจ้าหน้าที่ เลือกบัญชีอื่นที่ยืนยันอีเมลแล้ว มอบหมาย kyc_officer
2. เจ้าหน้าที่เข้าสู่ระบบของตน เข้าเมนูตรวจเอกสารในหน้าการยืนยันตัวตน
3. เปิดคำขอจริงและรูปครบ ตรวจข้อมูลก่อนตัดสินใจ อนุมัติเฉพาะหลักฐานที่ตรวจแล้วถูกต้อง หรือปฏิเสธพร้อมเหตุผลที่ผู้ใช้แก้ไขได้ ห้ามอนุมัติคำขอตัวเอง
4. สมาชิกเปิดหน้าสถานะและประวัติใหม่ ตรวจผลและเหตุผลให้ตรงกับเจ้าหน้าที่
5. เมื่อบัตรประชาชนหรือหนังสือเดินทางผ่านเงื่อนไข สมาชิกขอ Kao ID แล้วเปิดหน้าใหม่ ตรวจว่าได้ ID เดิม
6. ทดสอบถอนสิทธิ์จาก Owner เจ้าหน้าที่เดิมต้องโหลดคิว/หลักฐานและตัดสินใจไม่ได้

ยังไม่มีการแต่งตั้งเจ้าหน้าที่จริงหรืออนุมัติคำขอจริงโดยชุดทดสอบนี้ ผลใช้งานจริงต้องตรวจบนแอปของอ๊อฟ

## งานที่ยังไม่ถือว่าปิด
- แจ้งเตือนหมดอายุ ส่งเอกสารทดแทน/ต่ออายุและผลต่อสิทธิ์หลังเอกสารหมดอายุ
- SMS OTP จริง
- ทดสอบครบวงจรบนแอปด้วย Owner เจ้าหน้าที่ และสมาชิก
- คิวชุดนี้แสดง 50 รายการเก่าสุด งานแบ่งหน้า/ค้นหาคิวขนาดใหญ่ยังเป็นงานต่อยอด
- ระบบสองผู้อนุมัติยังไม่ได้กำหนด เพราะแผนเดิมยังไม่ได้ยืนยันว่าต้องตรวจสองชั้น
- การตรวจธนาคารชุดนี้เป็นการตรวจหลักฐานโดยเจ้าหน้าที่ ไม่ใช่การเชื่อมธนาคารเพื่อยืนยันเจ้าของบัญชีอัตโนมัติ

## Security advisory ที่ยังต้องติดตามก่อนเปิดบริการเต็มรูปแบบ
