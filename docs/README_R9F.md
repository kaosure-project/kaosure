# R9F — ระงับและคืนสถานะบัญชีกลาง

ติดตั้งต่อ R9E ซึ่งผู้ใช้ยืนยัน analyze สะอาด เทสต์ศูนย์ผู้ดูแล 6 รายการและรวม 230 รายการผ่าน พร้อมยืนยันหน้าแอปใช้งานได้แล้ว

## ใช้งาน
Owner -> ศูนย์ผู้ดูแล Kao ID -> จัดการบัญชีผู้ใช้ -> ค้นหาบัญชี -> สถานะบัญชีกลาง
ระบุเหตุผลอย่างน้อย 3 ตัวอักษร -> ระงับ/คืนสถานะ -> ตรวจรหัสบัญชีและยืนยัน
แสดงประวัติ 50 รายการล่าสุดพร้อมผู้ดำเนินการ เวลาและเหตุผล
กลับหน้าค้นหาจะโหลดข้อมูลบัญชีใหม่

## ขอบเขตที่ทำแล้ว
- เฉพาะ Owner โดยตรงดำเนินการได้ ห้ามระงับตนเองหรือ Owner คนอื่น
- เปลี่ยนเฉพาะ active <-> suspended; banned/closed ไม่ถูกคืนผ่านหน้าจอนี้
- การเปลี่ยนสถานะและประวัติบันทึกใน transaction เดียว การส่งซ้ำที่ได้สถานะเป้าหมายแล้วไม่เพิ่มประวัติ
- กันผู้ใช้เปลี่ยน account_status หรือ deleted_at ผ่านการแก้โปรไฟล์ของตน
- บัญชีถูกระงับไม่สามารถเขียนตารางบัญชี/KYC ที่ระบุใน migration หรือเรียกคำสั่งส่งบัตร/หนังสือเดินทาง/ใบพำนัก/ธนาคาร/ขอ Kao ID แม้ใช้ session เดิม
- Storage identity-documents ปฏิเสธการอ่าน/เขียนด้วยบัญชีที่ไม่ active ตาม RLS
- สิทธิ์เจ้าหน้าที่เดิมตรวจ active profile อยู่แล้ว จึงทำงานไม่ได้ขณะบัญชีถูกระงับ
- คืนสถานะแล้วบทบาทที่ยังไม่ถูกถอน/หมดอายุอาจกลับมาใช้ได้ ถ้าต้องการเลิกจ้างต้องถอนบทบาทแยกด้วย
- เก็บเอกสาร ประวัติ ผล KYC และ Kao ID เดิม ไม่ถือว่าเพิกถอน KYC
- รองรับเจ็ดภาษา

## ข้อจำกัดที่ต้องรู้
- ไม่ใช่การแบน Supabase Auth และไม่ได้ยกเลิก session/token ทุกเครื่อง ผู้ใช้อาจยังเข้าสู่ระบบ อ่านข้อมูลที่อนุญาต หรือใช้ขั้นตอนกู้คืนบัญชีได้ แต่คำสั่งบัญชี/KYC ในขอบเขตข้างต้นถูกตรวจฝั่งฐานข้อมูล
- รูปที่ดาวน์โหลดแล้วหรือ URL ที่ออกไว้ก่อนหน้าไม่สามารถเรียกคืนได้ด้วยการเปลี่ยน RLS
- ยังไม่มีหน้าสถานะระงับครอบทั้งแอป อาจเห็นข้อความล้มเหลวเดิมเมื่อพยายามทำรายการ; ไม่อ้างว่าระบบ session lifecycle ครบแล้ว
- ตารางและบริการนอก Kao ID รวมถึง Secondhand ต้องเชื่อมเงื่อนไขนี้ก่อนเปิดใช้บริการ ไม่อ้างว่าปิดสิทธิ์ทุกระบบแล้ว
- การเพิกถอน KYC และขอปิดบัญชียังเป็นงานถัดไป

## ผลทดสอบ
SQL rollback ผ่าน: ระงับ, ส่งซ้ำไม่เกิด log ซ้ำ, กันขอ ID, กันแก้โปรไฟล์/คืนสถานะเอง, กันระงับ Owner, คืนสถานะและอ่านประวัติ ทุกข้อมูลทดสอบย้อนกลับ ไม่มีบัญชีจริงค้างถูกระงับจากการทดสอบ
