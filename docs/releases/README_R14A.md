# Kao ID R14A — MFA และการตรวจสองคน

ชุดนี้รวมไฟล์ client ของ R12C, R13A และ R14A ต่อจาก R12B เพื่อไม่ตกหล่นส่วนที่เกี่ยวข้อง ไม่ใช่โปรเจกต์ Flutter เต็มชุด

## สิ่งที่เพิ่ม
- ตั้ง TOTP Authenticator ด้วยรหัสตั้งค่าแบบกรอกเอง ยืนยันรหัส 6 หลัก และเพิ่มอุปกรณ์สำรอง ไม่ต้องมี SMS หรือโดเมน
- ตรวจ MFA จากเซสชันและ factor ฝั่งเซิร์ฟเวอร์ ไม่เชื่อเพียงข้อความบนหน้าจอ
- คำสั่งสำคัญของผู้ดูแลต้องยืนยัน MFA ภายใน 10 นาทีเมื่อเปิดนโยบาย
- ตรวจเอกสาร บัตร/หนังสือเดินทาง/ใบพำนัก/ธนาคาร และหลักฐานคืนบัญชี ใช้สองบัญชีที่มีสิทธิ์ต่างกัน ทั้งอนุมัติและปฏิเสธ
- คนแรกเสนอผล คนที่สองยืนยัน หากไม่เห็นด้วย คำขอยังค้างเพื่อเริ่มตรวจใหม่ ไม่ตัดสินแทนกัน
- ความเห็นแรกหมดอายุ 24 ชั่วโมง หรือหลักฐานเปลี่ยน/ผู้ตรวจเสียสิทธิ์ ต้องเริ่มใหม่ ห้ามตรวจคำขอตัวเอง
- การคืนบัญชีสำเร็จยังใช้ Kao ID เดิม ไม่คืนสิทธิ์เจ้าหน้าที่อัตโนมัติ
- แจ้งเตือนเมื่อเพิ่ม/ถอด factor ที่ยืนยันแล้ว และเปิดนโยบาย โดยไม่ส่ง secret ในข้อความ
- Owner ดูจำนวนคิวตรวจและคิวอีเมลที่ค้าง/ผิดพลาดจากข้อมูลจริง
- service_context_r14a เป็นข้อมูลสถานะปัจจุบันสำหรับบริการกลาง ไม่ใช่ token SSO และไม่แทนการตรวจสิทธิ์ทุกคำสั่งที่เซิร์ฟเวอร์

Flutter ยังไม่ได้รันในสภาพแวดล้อมที่จัดชุดนี้ ตรวจได้เพียงไวยากรณ์ Dart และความตรงกันของ key ภาษา

## เปิดใช้อย่างปลอดภัย
สถานะหลังติดตั้งฐานข้อมูล: mfa_required=false และ dual_review=false จนกว่า Owner จะเปิดจาก UI ก่อนเปิดยังใช้กฎตรวจเดิม
1. เข้า ความปลอดภัย → การยืนยันสองขั้นตอน หรือไอคอนความปลอดภัยในศูนย์ผู้ดูแล
2. Owner ตั้ง Authenticator ให้ผ่านอย่างน้อยสอง factor บนอุปกรณ์อิสระ เก็บอุปกรณ์สำรองอย่างปลอดภัย ไม่ส่งรหัสตั้งค่าหรือ OTP ในแชต
3. แต่งตั้งเจ้าหน้าที่ตรวจ KYC อีกอย่างน้อยสองคน แต่ละคนใช้บัญชีของตนเองและตั้ง MFA ให้ผ่าน ระบบนับสองบัญชีอื่นที่ไม่ใช่ Owner
4. Owner ยืนยัน MFA แล้วกดเปิดนโยบายพร้อมยืนยันข้อความ หลังเปิด เมนูผู้ดูแลต้องใช้ MFA; ไม่มีปุ่มลดระดับหรือปิดการบังคับจากเว็บ
5. ให้เจ้าหน้าที่แต่ละคนทดสอบเปิดคิวและตรวจคำขอบัญชีทดสอบ ผู้สมัครเห็นผลเมื่อคนที่สองเห็นตรงกันเท่านั้น
บัญชีต่าง UUID ไม่ได้พิสูจน์ว่าเป็นคนต่างกัน Owner ต้องมอบหมายให้คนจริงที่ต่างกัน
การแต่งตั้งเจ้าหน้าที่ไม่ทำให้ผ่าน KYC และไม่ออก Kao ID อัตโนมัติ
Owner ยังจัดการสิทธิ์ พาร์ตเนอร์ และระงับฉุกเฉินเองได้ด้วย MFA ไม่บังคับสองคนสำหรับทุกการดูข้อมูล/ทุกคำสั่งบริหาร
ผลตรวจที่อนุมัติไปก่อนเปิดนโยบายไม่ถูกสร้างลายเซ็นย้อนหลัง

## กู้คืน Owner
อุปกรณ์หลักเสีย: ใช้ factor สำรองยืนยันและตั้งอุปกรณ์ใหม่ก่อนเลิกใช้อันเก่า
เสียทุก factor: ยังไม่มีระบบกู้คืนอัตโนมัติในเว็บ ต้องใช้การเข้าถึงโปรเจกต์ที่ได้รับอนุญาตและกระบวนการตรวจตัวตนแยก ผ่านเครื่องมือบริหาร Auth ทางการ พร้อมตรวจเซสชันที่อาจถูกขโมยและบันทึกเหตุการณ์ ห้ามคืน Owner เพียงเพราะอีเมลตรงกัน
ห้ามเปิดนโยบายก่อนทดลองอุปกรณ์สำรองจริง ทั้งนี้ MFA ไม่ป้องกันการขโมยเซสชันที่ผ่าน MFA แล้วทั้งหมด

## ผลทดสอบที่มี
SQL ใช้ข้อมูลชั่วคราวและ rollback: ตรวจ AAL จริง, MFA เก่า, กันข้ามบัญชี, กันเรียก executor โดยตรง, คนแรกไม่ตัดสินจริง, คนเดิมลงซ้ำไม่ได้, เห็นต่างไม่ปิดคำขอ, หลักฐานเปลี่ยนเริ่มใหม่, สองคนอนุมัติเอกสาร, คืนบัญชีพร้อม ID เดิมไม่คืนบทบาท, เงื่อนไขเปิดนโยบาย และสิทธิ์ดูคิว
การจำลอง factor/session ใน SQL ไม่ใช่ผลทดสอบรับ OTP จริงจาก Authenticator
เพิ่ม Flutter tests 20 รายการ แต่ยังไม่ได้รันที่นี่

## เกณฑ์ทดสอบบนเครื่องและเว็บทดสอบ
- ลงทะเบียน/ยืนยัน TOTP ของ Owner และเจ้าหน้าที่ รวมอุปกรณ์สำรอง
- MFA ผิด/หมดอายุ และเซสชันที่ยังไม่ผ่าน MFA ต้องใช้คำสั่งผู้ดูแลไม่ได้
- ถอดสิทธิ์ผู้ตรวจคนแรกก่อนคนที่สองยืนยัน ต้องไม่ใช้ความเห็นเก่า
- เปิด URL ตรงด้วยสมาชิกทั่วไปต้องเข้าเมนู/ข้อมูลผู้ดูแลไม่ได้
- สองคนเห็นตรงและเห็นต่าง; ผู้สมัคร/ผู้ตรวจคนเดิมต้องยืนยันครั้งที่สองไม่ได้
- ผล KYC, ธนาคาร, คืนบัญชี และประวัติต้องตรงกัน โดยไม่มี ID ใหม่หรือคืนสิทธิ์เดิม
- เปลี่ยนบัญชี/ออกจากระบบ/ออกจากหน้า ต้องไม่เหลือ secret หรือหลักฐานของบัญชีเดิม

## งานที่ยังไม่ปิด
- ทดสอบ Authenticator และวงจรจริงตามด้านบน รวม Flutter บนเครื่องอ๊อฟ
- การกู้คืน Owner เมื่อเสียทุก factor แบบมี workflow ในเว็บ
- การตั้งค่าป้องกันรหัสผ่านรั่ว/อัตราคำขอและตรวจ security advisors ของฟังก์ชันเก่าที่เหลือ
- ทดสอบสำรองและกู้คืนฐานข้อมูล/ไฟล์จริง ทดสอบโหลด และประเมินความปลอดภัยก่อนเปิดสาธารณะ
- SMS OTP และอีเมลแจ้งเหตุการณ์จริงยังรอการตั้งค่า/ทดสอบเดิม เมลยืนยันบัญชีเดิมคงไว้
- คิวตรวจยังจำกัด 50 รายการเดิม ไม่ใช่คิวแบ่งหน้าสำหรับปริมาณมากครบชุด
- การเงิน/ขนส่งของคำสั่งซื้อและการตรวจสิทธิ์รายคำสั่งทำต่อใน Marketplace
- ระบบองค์กรและตรวจ KYC อัตโนมัติเต็มรูปแบบยังเป็นงานแยก
ชุดนี้จึงไม่ใช่คำรับรองว่าปิดงานความปลอดภัยทั้งหมดหรือพร้อมเปิดสาธารณะแล้ว
