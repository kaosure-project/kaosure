# R10E — กลับมาใช้บัญชีเดิมผ่านการตรวจ KYC

ชุดนี้ต่อจาก R10D และรวมไฟล์ UI ที่จำเป็นของ R10C/R10D เพื่อให้ติดตั้งต่อเนื่องได้ ไม่เปลี่ยน Login/Register หรือการยืนยันอีเมลเดิม

## เส้นทางที่เพิ่ม
1. สมาชิกเข้าสู่ระบบด้วยบัญชีเดิมที่ปิดแล้ว ได้สิทธิ์เฉพาะหน้าขอกลับมาใช้
2. ส่งคำขอกลับมาใช้ → กด “ยืนยันตัวตนเพื่อกลับมาใช้”
3. เลือกบัตรประชาชนหรือหนังสือเดินทาง กรอกชื่อ/นามสกุล (รองรับชื่อเดียวและแสดงนามสกุลก่อน) วันเกิด วันออก วันหมดอายุ และแนบหลักฐาน
4. อัปโหลดในพื้นที่ส่วนตัว ส่งเข้าตาราง verification_requests และคิว KYC เดิม บัญชียังปิดอยู่
5. Owner/KYC Officer ที่ไม่ใช่ผู้ส่ง เปิดหลักฐานใหม่และหลักฐานเดิมที่มี ยืนยันว่าเป็นบุคคลเดียวกัน และใส่เหตุผล
6. อนุมัติ: ผล KYC คำขอกลับมาใช้ สถานะบัญชี และ Kao ID เดิมเปลี่ยนในธุรกรรมเดียวกัน ไม่ออกหมายเลขใหม่ ไม่คืนสิทธิ์เจ้าหน้าที่/ร้านค้า/ผู้ขายเดิม
7. ปฏิเสธ: บัญชีและ Kao ID ยังปิด สมาชิกเห็นเหตุผลและสร้างคำขอใหม่ได้
8. ยกเลิกคำขอ: ถอนออกจากคิวตรวจ ไม่ให้อนุมัติคำขอที่ยกเลิกแล้ว

ถ้ายังไม่เคยมี Kao ID การอนุมัติจะคืนบัญชีและผลตรวจเท่านั้น สมาชิกใช้ขั้นขอออก Kao ID เดิมภายหลังได้

## ขอบเขตสำคัญ
- รองรับ **บัญชีเดิม / User UUID เดิม** ที่ปิดด้วย R10D ไม่รวมโอน Kao ID ไปยังบัญชีสมัครใหม่อีก UUID
- อีเมล/เบอร์โทร/เลขเอกสารตรงกันอย่างเดียวไม่คืนสิทธิ์ ต้องตรวจหลักฐานโดยเจ้าหน้าที่
- เป็นการตรวจเอกสารด้วยเจ้าหน้าที่ ไม่มี OCR/ตรวจใบหน้า/liveness อัตโนมัติ คำว่า “หลักฐานใหม่” หมายถึงรายการส่งใหม่ ไม่ใช่ระบบพิสูจน์ว่าเพิ่งถ่ายภาพ
- บัญชีที่ถูกระงับ แบน ลบ หรือ Kao ID ไม่ได้อยู่ในสถานะ closed ไม่ผ่านเส้นทางนี้
- ผู้ที่มี Kao ID แต่ไม่เหลือหลักฐานอนุมัติเดิมให้เทียบ จะถูกบล็อกและต้องจัดการกรณีพิเศษต่อ ไม่ปลดล็อกด้วยการเดาข้อมูล
- ไฟล์ที่อัปโหลดแล้วเป็นแบบแก้ทับไม่ได้ หากเครือข่ายขัดข้องให้ใช้ไฟล์เดิมในการส่งซ้ำ หากต้องเปลี่ยนไฟล์ให้ยกเลิกคำขอแล้วเริ่มคำขอใหม่
- การส่งและดูไฟล์ของบัญชีปิดถูกจำกัดเฉพาะคำขอกู้คืนของตนที่ยังดำเนินการ ไม่เปิดสิทธิ์อ่านรูปเก่าทั้งหมดให้บัญชีปิด
- สิทธิ์หลังอนุมัติตรวจใหม่เมื่อเปิดเว็บ/กลับเข้าเว็บ/รอบตรวจ R10D (ประมาณ 15 วินาที)

## ติดตั้ง
ฐานข้อมูลติดตั้งแล้ว ไม่ต้องรัน SQL ซ้ำ ไฟล์ database/recovery.sql แนบสำหรับตรวจทาน

```powershell
$backupName = 'kaoid_before_R10E_' + (Get-Date -Format 'yyyyMMdd_HHmmss') + '.zip'
Compress-Archive -Path lib,test -DestinationPath $backupName
Expand-Archive -LiteralPath .\kaoid_account_recovery_R10E.zip -DestinationPath . -Force
flutter gen-l10n
flutter analyze
flutter test test/localization/recovery_r10e_test.dart
flutter test test/localization
```

หยุดแอปเดิมแล้วรันใหม่ด้วยคำสั่งเดิมของโปรเจกต์

## ผลทดสอบและข้อจำกัดของผล
SQL regression ผ่านและ ROLLBACK ทั้งหมด: ไม่มีสมาชิกจริงถูกปิด/คืน/อนุมัติระหว่างทดสอบ
- บัตรประชาชนส่งซ้ำไม่สร้างคำขอซ้ำ ใช้คิวตรวจเดิม
- ตรวจ RLS ว่าเห็นไฟล์ใหม่ของตน แต่เปิดรูปเก่าที่ไม่อยู่ในสิทธิ์ไม่ได้
- ห้ามอนุมัติตัวเอง ห้ามข้ามหน้ากู้คืนด้วย RPC ตรวจปกติ ต้องยืนยันการตรวจและมีเหตุผล
- เก็บและคืน Kao ID หมายเลขเดิม พร้อม audit เพียงครั้งเดียว
- บัญชีระงับคืนไม่ได้ เอกสารหมดอายุส่งไม่ได้
- ปิด/กลับมาใช้รอบที่สองได้
- หนังสือเดินทางยกเลิกแล้วหลุดจากคิวตรวจ และคำขอที่ปฏิเสธไม่คืนบัญชี
- ขอบเขตสิทธิ์เขียนชั่วคราวไม่ค้างหลังจบธุรกรรม

เพิ่ม Flutter widget tests 11 กรณี: สถานะรอตรวจทุก locale, โหลดผิดพลาดไม่กลายเป็นฟอร์มว่าง, ฟอร์มไม่ครบส่งไม่ได้, ตรวจการกู้คืนต้องยืนยันเพิ่มเติม
**ยังไม่ได้รัน Flutter analyze/test ที่นี่** เพราะไม่มี Flutter SDK การตรวจ ARB/วงเล็บไม่ทดแทน Flutter analyzer และ SQL ไม่ทดแทนการส่งไฟล์จริงผ่าน Storage/Auth

ตรวจแอปจริงด้วยบัญชีทดสอบที่ไม่ใช่ Owner: ปิด → เข้าบัญชีเดิม → ขอคืน → ส่งหลักฐาน → เจ้าหน้าที่เปิดภาพเดิม/ใหม่ → อนุมัติ → สมาชิกเห็น Kao ID เดิม และไม่มีสิทธิ์แอดมินกลับมา จากนั้นตรวจกรณีปฏิเสธ/ยกเลิกแยกต่างหาก

## งานค้างนอกชุดนี้
การเชื่อมบัญชีสมัครใหม่กับตัวตนเดิม, ขั้นตอนกรณีไม่มีหลักฐานเก่า, เงื่อนไขปิดบัญชีที่มีประวัติบริการ, เพิกถอน KYC, เอกสารหมดอายุ/ต่ออายุ, นโยบายเก็บ/ลบข้อมูล, SMS OTP จริง, อีเมลแจ้งเหตุการณ์จริง และทดสอบโหลด

Security advisors ของฟังก์ชัน public/extension/Auth เดิมยังมีรายการต้องตรวจต่อ ตาราง private ใหม่ตั้งใจไม่ให้ client policy อ่านหรือเขียนตรง ไม่ประกาศว่าทั้งระบบพร้อม production
