# การเปลี่ยนแบบ Kao ID เป็นระบบจริง

## R1 — พร้อมติดตั้ง / รอตรวจ runtime
โครงสร้าง Home / Account / Security / Settings, responsive shell,
route ที่มีชื่อและ guard เดิม, ซ่อนฟีเจอร์ที่ไม่มีการทำงาน, ภาษา TH/EN
ไม่เปลี่ยนแหล่งข้อมูลสิทธิ์หรือสถานะตัวตน ไม่สร้างสถานะ verified/หมายเลข Kao ID จากต้นแบบ

## งานที่ยังต้องทำหลังตรวจ R1
1. Account/Edit profile: จัดรายละเอียดหน้าตามแบบใหม่ ตรวจข้อมูลติดต่อและรูปจริง
2. Auth/Phone verification: ใช้หน้าที่มีอยู่ แปลให้ครบ ปรับรูปแบบตามแบบใหม่ ตรวจ error และ recovery flow
3. KYC/Identity/Issuance: นำข้อมูลสถานะจริงเข้า UI และแสดงขั้นตอนตาม backend ที่รองรับ
4. Security: เปิด devices/sessions/history/MFA ทีละฟังก์ชันหลังตรวจและทดสอบจริง
5. Settings: privacy/notifications/support/terms เมื่อมีระบบและเนื้อหาจริง
6. บริการ: แสดงเมื่อเปิดบริการแล้ว สมัคร service membership เชื่อมกับ Kao ID เดิม
7. Business/Governance: ตรวจเส้นทางและสิทธิ์ก่อนเปลี่ยน UI สำหรับผู้มีอำนาจ

## หลักการ
- หน้าเดียวมีหน้าที่หลักชัดเจน ไม่เพิ่มเมนูที่กดแล้วไม่ทำงาน
- หน้าหลักใช้สถานะจากข้อมูลจริง ไม่ใช้เปอร์เซ็นต์ UI เป็นเกณฑ์สิทธิ์
- เก็บชื่อ/รหัสผู้ใช้เป็นข้อมูล ไม่แปล domain codes หรือสร้างตัวตนใหม่
- เพิ่มบริการภายหลังโดยแยก service profile/membership จาก central identity
- ทุกชุดต้องผ่าน analyzer, tests ที่เกี่ยวข้อง และตรวจ UI/flow จริงก่อนปิดงาน
- ต้นแบบ 40 หน้าไม่ใช่หลักฐานว่าฟังก์ชันทั้ง 40 พร้อมใช้
